# Bounce Lite V0.1.2 Vitality–Physics Separation Implementation Plan

> **Execution:** Follow this plan sequentially in the current workspace. Use TDD for every deterministic behavior. Do not create a worktree, sub-agent, formal asset, audio system, new game mode, or unrelated UI refactor.

**Goal:** Replace Energy-driven velocity reconstruction with independent Physics and Vitality domains while preserving the V0.1.1 Endless prototype loop.

**Architecture:** `BallController` owns CharacterBody2D motion and orchestrates collision settlement. `SurfaceResponseModel` is a pure calculator that returns a `SurfaceCollisionResult`. `BallVitalityModel` owns only vitality bounds and ActivityState. Local signals distribute settled events to `BallVisuals` and `EndlessRules`.

**Tech Stack:** Godot 4.7 stable, GDScript, CharacterBody2D, Compatibility Renderer, dependency-free headless tests.

**Approved Spec:** `docs/superpowers/specs/2026-09-08-v0.1.2-vitality-physics-separation-design.md`

**Refactor Baseline:** `18c1931 chore: snapshot v0.1.1 endless prototype baseline`

**Godot Console:** `D:\Apps\Godot_v4.7-stable_win64\Godot_v4.7-stable_win64_console.exe`

Add explicit tests for:

```gdscript

    "changing Vitality does not rebuild Velocity")
```

Also assert:

- a full-Vitality Ground hit uses `0.78` restitution for current response, then leaves Vitality at `0.65`;

- repeated successful Paddle hits never exceed `520 px/s`;
- invalid Paddle contact has Wall-like behavior;
- repeated simulated Ground arrivals eventually enter RESTING;
- Wake sets Velocity to `330 px/s` and Vitality to `0.85` independently;
- settled signals expose post-settlement values.

When simulating repeated Ground hits without a scene, turn the outgoing vertical component downward before the next call so each call represents a new arrival rather than reflecting an already departing Ball.

### Step 3: Replace Controller collaborators

Change fields to:

```gdscript

var surface_response_model: RefCounted
```

Remove:

- persistent speed mapped from Energy;
- `_sync_velocity_from_energy()`;
- `speed_for_current_energy()` calls;
- collision branches that directly implement Surface rules.

`start_active(initial_direction)` must explicitly set:

```text

```

### Step 4: Implement the approved settlement order

Inside `resolve_surface_collision()`:

```text
capture before state
→ resolve pure CollisionResult
→ apply velocity_after
→ vitality_model.apply_delta(result.vitality_delta)
→ vitality_model.resolve_activity(result.settle_allowed)
→ zero Velocity only if state became RESTING
→ update visuals
→ emit settled events
```

Keep the top-face validity check in the collision-detection adapter because it depends on CharacterBody2D contact orientation. Pass only the resulting boolean into SurfaceResponseModel.

### Step 5: Migrate Wake

Wake stays outside SurfaceResponseModel:

```text
vitality_model.wake(max_vitality * wake_vitality_ratio)
velocity = wake direction * wake_speed
```

Do not derive either value from the other.

### Step 6: Update main signal adapters

Rename Energy-named callback arguments to Vitality. Preserve existing Combo and Timer calls exactly.
