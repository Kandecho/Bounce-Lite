## 2. 全阶段契约与分工

固定 lifecycle：ACTIVE → DECAYING → RESTING → Wake 或 Continue → ACTIVE。
Wake 由挡板动作直接触发，力度强；Continue 由球停稳后发起，力度弱，互动只提供资格。
没有输入只是输入事实，不推断玩家在观看、离开或注意力状态。
E01 的有限接触影响保留；没有分数、必收集目标或任务清单。

每阶段启动时明确具体文件清单；共享 Main、tuning、场景和测试入口由核心代理单独编辑。
若某文件需要不同角色协作，先交付接口或建议，再由其唯一负责人修改。
主代理不直接编写运行时代码或测试修复；发现问题交回 low 实现代理。
是否提取更多 Behavior 类不是本阶段先决条件，不为了结构完整预建通用系统。

Physics 提交位置、速度、碰撞和支撑结果；Interaction/Behavior 只能发明确请求。
世界继续提供环境采样及活力请求，不持有并直接改写 Ball 运动。
Feedback 只呈现已提交的结果，不能决定气流、碰撞、启动或活力变化。

## 3. 阶段一：转子与能量块随机出现

### 希望玩家经历的瞬间

世界出现一个可以靠近的对象，玩家试着接球、让开或改变接触点。
球与对象发生一次可理解的接触，余波使玩家想再试一次；对象离开后仍能自然地玩。
随机决定何时、何处、出现多久，对象出现后的碰撞、补能与气流规则保持可学习。

### 已定范围

- 转子和能量块只在事件有效区出现，出现时间、位置和停留时间允许随机。
- 不能生成在球当前所在位置；补能只由真实重叠提供，不吸引轨迹或触发启动。
- 按设计说明第 5 节的离场方向，顾及转子余转和球的邻近关系，避免正在参与轨迹时突然撤走气流；“转速足够低”“球不在附近”的具体判据尚待实施验证。
- 世界对象断续出现后重新评估挡板补能，避免能量块成为维持互动的必需品。

### 实施建议与参数决策

以下是可靠性实现建议，不是用户原话或已确认参数：

- 生成点计算纳入对象几何半径，保证对象实体完整落在有效区内。
- 候选点检查球的真实圆形范围及必要间距，并避免新对象与已有实体不合理重叠。
- 找不到合适位置可推迟出现；不要用强移球、穿透或无限重试满足生成计划。
- 随机源应可复现；开发记录保存种子与事件时序，便于回放具体失败。
- 明确出现、可交互、等待离场、消退与移除的责任顺序，具体状态实现从简。
- 消退时气流、碰撞和可见实体保持可解释的一致生命周期，不能留下不可见碰撞体。
- 实施时比较延迟离场与可读消退：安全条件未满足时推迟，不把有余转绝对不能离场或固定距离阈值提前写成新设计限制。
- 数量、尺寸、出现间隔、停留时间从真实运动下的接触机会和空场时段决定。
- 比较不同种子及跟随、让开、间歇输入下的事件间隔，不只追求平均碰撞次数。
- 将停留时间与连续两次接触的机会一起观察，判断叠加、反转是否有机会被体验。
- 挡板补能比例与能量块补给量一起试调；保留没碰到能量块也可继续互动的片段。
- 临时数值由实现代理提出并记录依据，主代理实际观察后调整，不逐项要求用户定值。

### 文件与交付接口

世界代理负责 `play_world.gd` 生命周期和生成逻辑、`test_play_world.gd` 的可复现覆盖。
核心代理负责 Main 提供的有效区及必要的 Ball 几何只读信息，独占所有接线修改。
反馈代理仅在需要新出现/消退表现时改 `world_feedback.gd`，不控制实体生命周期。
保留现有加速度采样与活力请求；若新增事件，先约定事件发生时物理状态已到哪一步。
开发对照应能回到固定对象方案或关闭本阶段变化，不另建产品设置界面。

### 回归与结束证据

- 修改确定性行为前先增加可复现回归，包括固定种子与边缘生成条件。
- 验证生成范围包含半径、球邻近拒绝、无可用点推迟及多对象重叠策略。
- 验证退出期间无幽灵碰撞、失效对象不补能、移除后采样不再贡献环境力。
- 保留真实重叠节流、驻留恢复、转子记忆和加速度上限测试。
- 跑确定性、世界、组合与物理场景；涉及事件声音时跑音频场景。
- 实际捕获出现、交互、等待离场及离场后画面，默认640×480也检查可读性。
- 结束记录种子、输入轨迹、事件时序、异常恢复与未解决问题，并完成导入和1200帧主场景。
- 通过表示可进入阶段二，不表示随机节奏或整体体验获用户验收。

## 4. 阶段二：Continue 资格与 Wake/Continue 强弱、表现

### 希望玩家经历的瞬间

一次有意义的挡板介入留下后续可能；球短暂停稳后自己接上一段较轻的运动。
玩家直接发起 Wake 时，动作与表现明显更强；两者都保留真实空间阻挡和安静的可能。

### 已定范围与未定选择

- 识别挡板动作而不是鼠标像素；需要有效挡板动作才能获得 Continue 资格。
- 资格具体判定未定：真实有效接触、球在空中且附近的定向挡板动作等只是候选。
- 是否组合候选、有效距离、方向条件和重复资格处理，通过具体片段与反例决定。
- 资格时间窗的起点和时长需重新选择，旧15秒是现场参数，不是正式约束。
- 固定 lifecycle；短暂停顿与较深安静由时间、支撑和互动关系表达。
- Wake 强、Continue 弱已定；同时检查启动速度和活力恢复，避免两个通道表达相反。
- 原型速度350/290方向一致，但活力恢复0.15/0.22相反；后续调整不沿用为定值。
- 明显残留圈表现移给 Wake，Continue 改为更接近球自身运动过程的反馈。
- 挡板正上方仍可真实阻挡起跳；不以穿透或改写固定起跳关系掩盖空间问题。

### 文件与责任

核心代理独占 `paddle_controller.gd`、`ball_controller.gd`、`play_rhythm.gd`、Main和必要tuning。
先写清“动作事实 → 资格/请求 → Physics提交 → Feedback通知”的接口和事件顺序。
核对两处现有实现与目标的差异：`apply_resting_interaction()` 先调用 `vitality_model.wake()`（会同步发 Activity 通知），随后才提交必要的启动速度；而 Continue 已先提交速度。另一个差异是 `wake()` 按活力阈值选择 Activity，恢复后不保证进入 ACTIVE 枚举。阶段二需明确并对齐固定 lifecycle 和提交顺序，不能只修改描述；具体参数或实现方法留在该阶段决定。
反馈代理负责 `ball_visuals.gd`、`world_feedback.gd` 及必要声音接收端。
碰撞、Wake的真实活力传递仍驱动挡板变暗，Continue不伪装为挡板供能。
保留旧资格与表现的开发对照，避免一次改动后失去判断差异的依据。

### 回归与结束证据

- 先覆盖候选判定的正反例：真实动作、无效远处动作、目标变化但实体未移动、重复输入。
- 验证资格获得/消耗/过期、一次机会、无输入时不自动推断观看或制造无限继续。
- 覆盖Ground/Paddle支撑、失去支撑、强Wake、Continue及挡板底面阻挡。
- 验证运动先提交、Activity通知不改Physics，补能不隐式启动，反馈不能反向改运动。
- 更新强弱相关的明确断言，不批量放宽无关物理/E01/几何断言。
- 跑确定性、物理、组合、E01和受影响音频场景，捕获两种启动及安静状态。
- 主代理比较真实轨迹与声画，记录资格方案、临时参数理由和仍需用户判断的瞬间。
- 完成导入和1200帧主场景；符合边界后进入完整试玩，不能据参数大小宣称伙伴感成立。

## 5. 阶段三：完整试玩与收口

自由玩几分钟，允许接、等、让开、错过对象和停手，不要求逐项完成任务。
主代理先检查默认窗口和缩放、完整主循环、资源释放、运动边界及对照入口。
用户重点描述具体瞬间：是否想再次回应、随机出现是否可参与、短停与安静是否自然。
记录机器结果、主代理观察、用户体验结论三类证据，不能相互替代。
按体验决定保留、变形或搁置；需要返工时重派对应low负责人并补适用回归。
阶段结束报告实际文件、参数选择依据、验证环境、人工结论和剩余问题。
合入main或推送远端需后续明确指令；完成度与代码量不构成自动合入理由。
