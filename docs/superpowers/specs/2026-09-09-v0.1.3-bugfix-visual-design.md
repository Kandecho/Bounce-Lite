## 2. 几何与异常恢复

- 场景中的内碰撞面为 left=173、right=788、top=133、ground=581。Main 从实际 CollisionShape2D 推导 arena，不能从 Panel 或 Paddle 输入边界推导。
- Ball 半径 16，Godot safe_margin=0.08；目标安全中心区域为 x=[189.08,771.92]、y=[149.08,564.92]。
- Paddle 场景中心 Y=537，尺寸 150×18；稳定 Ball 顶部约 548.92、Paddle 底部 546，间隙约 2.92 px。运行时高度读取场景，不再维护重复常量。
- Ball z_index=1，Paddle 为 0；HUD 保持原层级；开发面板置于 DebugOverlay CanvasLayer 10，统一覆盖游戏对象和 HUD。
- Ground 响应允许 settle 且 Ball 为 RESTING 时，将已接近地面或已穿透的球收敛至 ground_top − radius − safe_margin。空中的弱 Wake 不吸附地面。
- 保留原有 settle 速度清零、Rest 计时重置、Wake 消费标记复位；不额外修改 Vitality。
- 正常运动仍由 move_and_collide 与 SurfaceResponseModel 处理。运动前（包括 RESTING 早退前）及运动后检测异常越界；只在超出安全区域及 0.12 px 求解容差时恢复最近安全位置，移除仍指向外侧的速度分量，保留向内及切向运动。
- 低 Vitality 的 Ground 侧越界恢复为稳定 RESTING，不额外反弹、恢复或扣除 Vitality。异常恢复清空 Trail 历史，避免跨位置跳变连接残影。
- bounds_recovered 与 bounds_recovery_count 用于开发诊断，不增加 UI。正常轨迹测试要求该计数不增长。

Paddle 仍继承 CharacterBody2D，但用直接位置平滑驱动，没有 sweep。底角多重约束的异常位置恢复属于本轮兜底；高速 sweep 仍为后续需复现才评估的问题。

## 3. Wake 与领域边界

apply_resting_wake_impulse(paddle_velocity, paddle_position) 只在 RESTING、未消费、休息时间达到 0.12 s、横向邻近且非零水平输入时接受。

- 固定重力 260 px/s² 已获用户试玩确认，用于改善整个 Ball 的纵向活动范围，替代旧 520。
- 邻近判断：Ball 与 Paddle 中心横向距离 <=200 px；不再由半宽与 margin 推导。
- RESTING 首个弱样本开启 50 ms 窗口，保留模长最大的样本及其方向；强样本立即提交，不等待窗口结束。窗口结束提交弱冲量，最迟为下一物理 tick（30 Hz 下约 66.7 ms）。离开范围取消待提交样本；重新开局或 settle 清空样本。
- impulse = (vx×0.18, −abs(vx)×0.70)，限制为 max_speed。
- 单次冲量加到当前 velocity；未达到 impulse.length()=180 px/s 时保持 RESTING、不恢复 Vitality。
- 达到阈值增加 max_vitality×0.15，默认进入 DECAYING；阈值对应 Paddle 速度约 249 px/s；500 px/s 输入产生 (±90,−350) px/s 冲量。
- 每次停稳最多接受一次冲量；Ground 再次 settle 后复位并重启 Rest 窗口。
- 返回 bool 仍表示实际激活，而非“接受了任意冲量”。wake_impulse_applied 信号表达实际已提交的弱/强事件，统一驱动 Rules 强 Wake 计时与 Paddle 瞬时反馈。
- Main 连接 Paddle 输入 → Ball，收到已提交的强 Wake 信号后通知 Rules 重启活跃计时；不额外迁移规则层。
- 正常 Paddle 顶面下降接触可恢复最大 Vitality；侧面/下侧接触保持既有 Wall-like 响应。新增 paddle_contact 信号保留原始接触位置和有效性，避免视觉将无效接触误报为成功。

Paddle 始终为真实 Surface，包含 Wake 期间：挡住路径时下沿碰撞是正常结果，玩家可移开挡板。禁止临时忽略碰撞、传送球到挡板上方或随机 impulse；不以 Wake 到达顶板为验收条件。Blocked Wake 应能正常落稳并再次开放输入，不永久卡碰。

SurfaceResponseModel、BallVitalityModel、EndlessRules 的公式与职责保持不变。

## 4. 冻结视觉实现

视觉目标以 visual_spec.md §1.1、§8.5、§11.4–11.5 为准。统一实现 token 位于 scripts/config/visual_tokens.gd。

- Core 色相 H=189°，S/V 随 Vitality；RESTING 使用固定 v=0 的状态色。抗锯齿，无高光点。
- Glow 使用缓存的 GradientTexture2D 径向纹理，轮廓外 alpha=peak×(1−t)^1.6，t=(d−1)/0.75；1.75r 归零，56 px 包络。peak 为 lerp(0.25,0.85,v)，RESTING 固定 0.25。
- Glow 不读取 Velocity 或事件脉冲；不随 squash/stretch 改变包络。Ball 只保留瞬时几何形变，去除独立 glow_pulse / darken_pulse。
- Trail 每 0.085 s 采样世界坐标，跨物理帧插值采样时刻；显示 clamp(round(4×speed/max_speed),0,4) 个离散残影。
- 为同时满足时间采样与最低 18 px 间距，从时间采样历史沿路径插值选取残影；目标间距 max(speed×0.085,18)。额外历史仅用于取样，不增加可见残影数。历史不足时不凭空生成位置。
- 残影直径 1.00→0.82 倍、alpha 0.34→0.05，并乘 lerp(0.30,1,speed/max_speed)；固定满 Vitality Glow 色，共用径向贴图。停止或异常恢复清空历史。
- Paddle 基础/闪光/扰动色为 #45786E / #6FE0BE / #E6FFF6，无常驻发光。有效接触 1.0、无效 0.28 且去饱和；弱 Wake 连续 0.15–0.45、强 Wake 0.85。
- 接触点反馈用两段 22 px 亮段及 7 px 刻度，沿本地接触点展开并裁在胶囊直边范围。可选 Paddle squash 本轮不加。
- Dark panel=#171C26、边框=#3A4350、外部底色取现有 dark.window=#242B37；HUD 使用既有文字 token。没有制作完整主题窗口装饰或切换系统。

### 反馈时间口径

冻结曲线 τ=55 ms：140 ms 时强度约 7.84%，读作“接近基础色”；120/150/220/260 ms 是无效接触/弱 Wake/有效接触/强 Wake 的完全截止时刻。局部扰动额外乘该指数包络和规格中的 progress 衰减，不允许长尾保持高亮。此处将“约 140 ms 退回”与原事件持续时间放在同一曲线解释；主观是否足够短促仍由试玩判断。

## 6. 基线收口与已知遗漏（2026-09-09）

V0.1.3 bug fixes及冻结视觉已完成并获用户验收：Paddle / Ground Resting Ball几何间隙、越界恢复、弱Wake重落Ground的penetration/settle、统一调试覆盖层，以及200 px /50 ms /0.70 Wake校准；重力260保持。Paddle始终真实碰撞，未引入collision exception。

本次回归：确定性381、物理场景803、音频场景38通过。原V0.1.3截图是历史验证证据，本轮未改视觉。

**Paddle Resting Support：pending / investigation，未实现。** 当前RESTING是活动状态，不是统一support surface记录；零速度RESTING会提前返回。正常有效Paddle顶面碰撞恢复活跃，不是停靠；RESTING弱Wake后的Paddle接触不走有效反弹入口，只有Ground settle会复位单次Wake消费。因此可能出现支撑后无法重新Wake或移开Paddle后缺少支撑丢失处理。此项为代码诊断，不宣称已复现所有自然输入路径。

最小适配需明确support归属、Paddle上settle/消费复位、支撑移开后的重力恢复与Wake资格，并补对应场景回归；具体设计仍待确认，本轮不改。既有Paddle sweep和configure开局副作用也保持已登记未修复。
