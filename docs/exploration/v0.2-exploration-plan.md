## 1. 搜索目标与基准

核心问题：什么样的事件，会让玩家产生“我和它在玩”的感觉？

第一阶段比较不同关系来源，避免围绕一个机制连续打磨后才接触其他方向。首批覆盖接触语言、共同改变第三对象、停顿中的连续感，以及世界介入后的即兴回应。它们不是 V0.2.0 的四项必做功能，也不预设实验最终必须组合。

规划时仓库为 main，工作区干净，代码基准为 `f4c7299`，已有 `v0.1.6` 标签。当前 main 具备碰撞、Paddle 支撑、弱交互与 Strong Wake、程序化视觉及基础声音。已知限制和历史机器验证见[V0.1.6 收口报告](../reviews/v0.1.6-consolidation.md)；本轮未运行游戏测试，也未补做人工体验验收。

当前输入主要记录位移量，Wake 使用固定启动，尚无实验所需的完整意图语言；有效 Paddle 碰撞恢复全部缺失活力。这些事实用于解释对照结果，不据此排除接触实验或能量对象。既有休息模型也不决定未来 wake／rebounce 必须怎样划分。

实验启动时先重核 Git 状态与基准，并短暂回看现有体验，区分既有现象与实验新增现象；不要求先完成一轮无关的架构清理。

## 2. 首批搜索顺序

| 顺序 / 编号 | 希望出现的瞬间 | 主要区分的方向 | 建议分支名 |
| --- | --- | --- | --- |
| 1 / E01 | 换一种接触，球作出可理解但不受完全控制的回应；玩家自发再试 | 伙伴感是否可以来自接触语言 | `codex/exp-001-contact-language` |
| 2 / E02 | 玩家与球反复改变同一个第三对象，开始关心它接下来会怎样 | 伙伴感是否可以来自共同影响世界 | `codex/exp-002-shared-object` |
| 3 / E03 | 球停了一下，互动似乎仍在继续；再次介入也可能像新开始 | 伙伴感是否可以存在于停顿和时间关系中 | `codex/exp-003-pause-continuity` |
| 4 / E04 | 世界改变了原来的轨迹，玩家顺势产生新的行动想法 | 伙伴感是否可以来自一起应对变化 | `codex/exp-004-world-interruption` |

先用 E01 与 E02 拉开“直接接触关系”和“共同对象关系”的差异，再用 E03 与 E04 比较“减少动作仍有关系”和“增加世界变化是否有关系”。顺序依据区分度，不依据最容易实现的功能。

建议先做 E01、E02 两个可玩片段并试玩，再继续 E03、E04；前两项的观察可以调整后两项的呈现，但不应自动把整个首批改成对一个机制的细调。每次只推进一个实验，不要求子 Agent、并行实施或 worktree。

## 3. 实验卡

以下手段是起始建议。获准启动后，开发者可在同一体验假设内选择更合适的临时实现，无须让用户先定每个事件条件或数值。改变主要假设时，记录为变体或新实验。

### E01：接触形成语言

**假设**：当接触方式带来可学习、可感知且依赖球当前运动的差异时，玩家会自发重复或改变动作，体验到双方的往来。

- **事件片段**：玩家接到球，下一次换一种接触位置或时机；球的回应有相似规律，也受自身运动影响，玩家想再确认一次。
- **最小可玩范围**：球、挡板和原有场地；开发者先选择一个主要接触变量，产生两种可辨认的运动回应，并提供足够清楚的接触反馈。不加目标物或收集结果来解释操作。
- **可选手段**：接触位置、挡板接触瞬间运动、接触时机或反馈差异。第一版不叠加全部变量，不强制从 Wake 开始，不先加入随机因素。若采用速度偏置，仍须保留碰撞前运动与真实接触的作用。
- **对照**：保留原接触回应的版本；尽量保持场地、初始条件和表现清晰度相近。必要时再做单独反馈变体，区分“反馈更明显”与“动作关系更有趣”。
- **关键观察**：玩家是否自发改变动作来验证规律；能否描述自己的影响；是否只是练习把球准确送到指定位置，或始终感觉与动作无关。
- **下一步依据**：规律可感知但像瞄准工具时，变形为较弱或更依赖情境的回应；只有反馈吸引人时，转向接触表现假设；形成自发往来时保留候选。故障导致不可读时先修复，不将其当成自主性。

### E02：一起改变一个东西

**假设**：玩家通过挡板参与球的运动，而球持续改变一个第三对象，能让玩家形成共同关注与“一起做了某件事”的感觉。

- **事件片段**：球碰动一个物件，物件的新位置或姿态改变下一次机会；玩家希望球再碰一下，也可能临时改变想法。
- **最小可玩范围**：只增加一个能被球改变、变化会短暂保留的对象。首选可摆动的小片；同等成立的可移动环或其他对象可替换。一次接触之后仍有可关注的后续。
- **可选手段**：接触改变物件位置、姿态或下一次相遇方式；玩家通过已有的真实挡板介入。无需让球获得新人格或主动追踪目标。
- **对照**：同一对象的变化不保留／较快复原版本，用来比较持续共同影响是否重要。对象不必被命中，试玩不下达“碰它若干次”的指令。
- **关键观察**：玩家是否主动关注这个对象、试图改变下一次相遇；是否觉得自己参与了变化；是否只在旁观一段自动装置表演。
- **下一步依据**：存在明确共同注意时保留；介入机会不足时先让参与变得可读再判断；只有物件动画有趣时搁置或改写假设。能量奖励可作为后续独立变体，不在本实验中一并引入。

### E03：停下来以后，互动还在吗

**假设**：合适的停顿与继续方式可以保留互动的连续感；较长间隔后的介入也可能自然产生新开始感，而无需先分成两套机制。

- **事件片段**：一次往来之后球短暂停下；玩家可以继续轻触、等待或重新介入，体验这段关系是否还在延续。
- **最小可玩范围**：仍只有球和挡板；用一条临时停顿／继续路径分别体验短间隔与较长输入沉默。保留自然出现这两种情境的机会，不要求玩家持续证明自己在场。
- **可选手段**：回应延迟、轻微几何回应、有限恢复或再次启动的时机。先选一种主要手段；是否采用自主恢复由实验需要决定，不提前规定 wake／rebounce 独立状态或新 Behavior 层。
- **对照**：使用相同继续手段比较不同间隔，或与原有立即强回应比较；首轮不同时改变等待时长、恢复量、方向、声音与视觉全部因素。
- **关键观察**：玩家是否仍认为自己在互动；什么时候觉得结束了；回来时是否感到接续或新开始；是否出现等待程序、反复催促或照料负担。
- **下一步依据**：先记录玩家实际感知的区分。确有区别才探索不同表现；没有区别就保留共享机制的可能。没有输入不等于离开，没有差异也不能靠解释性标签补造差异。

### E04：世界打岔，产生下一步

**假设**：能够看出原因的世界变化打断预期轨迹后，会让玩家与球出现新的即兴互动，而不仅是观看特效。

- **事件片段**：球正在经过某处，世界因素使它偏离预期；玩家随之改变接法、等待位置或临时产生的新目标。
- **最小可玩范围**：一次局部、可辨认的世界作用及其运动后果；没有倒计时、成功窗口或要求避开的障碍任务。
- **可选手段**：局部气流、引力变化或一个临时弹性结构，只选一个能清楚呈现事件的手段。机制选择服从这个片段，不预建风场／环境调度系统。先采用稳定条件，实际轨迹参与结果，不偷偷按玩家意图安排必然落空。
- **对照**：作用关闭版本与作用开启版本；开发者可准备相近初始条件观察差异，但试玩时不要求精确复演输入。
- **关键观察**：变化后玩家是否产生新的行动；是否能把自己的行动与后续联系起来；是否觉得世界只在捣乱、削弱控制，或只有特效很酷。
- **下一步依据**：出现即兴配合时保留；关系来自等待或第三对象时据此变形；只有一次惊讶、无法读懂原因或没有后续互动时搁置或先修正可读性。

## 4. 第二轮候选池：由观察选取，不全部排产

| 首批发现或未解问题 | 下一轮事件种子 | 新假设 |
| --- | --- | --- |
| E01 的重复动作让人想继续 | “再来一次”：相似介入留下短暂影响，下一次有相似但不同的后续 | 重复与变化能否形成双方发现的玩法 |
| E02 有共同关注，但缺少再次靠近的理由 | 一个可触发明确活力效果的能量对象，效果留在后续运动中 | 玩家自发追求奖励，能否增强共同互动而不形成任务 |
| E02 的变化很快被遗忘 | “留下点痕迹”：球与物件的接触留下短暂可改变的印记 | 共同历史是否让下一次更值得关注 |
| E03 停顿成立，继续仍像按钮 | “迟到的回应”或“轮到你”：比较回应时机和留白 | 时间关系是否比启动强度更重要 |
| E04 的改变催生新想法，但因果过于短暂 | “余波还在”：介入结束后世界状态仍持续片刻 | 延续的后果是否连接玩家与球 |
| 动作反馈比新对象更有吸引力 | 偶然形成又错开的接触节奏 | 声音与运动的配合能否引出自发再试 |

能量块、明确效果与奖励均在可探索空间内，不因当前 Paddle 已恢复活力而排除。需要实验说明新增对象带来什么经历，允许临时调整相关参数以让差异可感知，并记录偏离。没有必须收集、评分或完成清单。

## 5. 快速实验的工作方式

1. **定一个问题**：从事件片段写一句体验假设，注明最重要的对照和会改变判断的观察。无需先设计完整行为表。
2. **做出片段**：在分支用足够可靠的临时实现呈现；允许参数、事件、行为和反馈随假设调整。先解决漏输入、卡住、假接触等会污染观察的问题。
3. **到点试玩**：玩家已经能遇见片段、察觉影响并再次尝试时就进入试玩，不为了通用化、美术完成度或长生命周期继续扩建。若事件无法在短次试玩内遇见，可用开发者启动条件提供机会，但不能预写玩家成功结果。
4. **有针对性地改一轮**：可读性或力度问题允许快速调整；连续微调没有增加新的体验证据时，记录后转向另一个方向，不把搜索拖成机制完善。
5. **作判断并转向**：根据具体片段给出保留／变形／搁置建议。没有用户试玩证据时，只能标为待试玩，不以开发者喜欢代替结果。

不以完成全部实验数量或固定时长作为成功指标；也不把首批变成正式功能承诺。第一轮同时改变太多关系时，优先拆开观察；同一假设确实需要多个机制时可以合做。

## 6. 试玩与记录

每批给用户少量彼此不同的片段，提供明确的构建／分支对应与基本操作说明。先自由体验，避免提前告诉玩家“这里应该像伙伴”或布置命中任务。之后再用具体问题回顾：

- 哪一刻自然想再试一次，随后做了什么？
- 哪一刻觉得自己和球一起改变了什么？
- 哪一刻只是觉得系统很酷，或在等程序、被要求完成事情？

无需用户逐项批准参数，无需量表评分或玩家遥测。先保留用户对实际片段的描述，再写开发者解释。可以用相近初始条件、关闭事件的对照、反馈简化后的复看帮助区分关系与新鲜感；不要求完全复演操作。

每项实验只维护一份简短记录，随对应分支保存；候选筛选时再把必要结论整理到 main 文档。记录模板：

```text
实验 ID / 变体 / 基准提交 / 实验提交 / 启动方式：
主要假设与事件片段：
相对基线的临时改动；对照保留了什么：
机器检查结果与已知问题：
用户试玩的具体片段与原意；尚未观察到什么：
开发者解释（与观察分开）：
结果：保留 / 变形 / 搁置；或尚待试玩，暂不下结论
下一次只想弄清的问题：
```

不把代码 bug 导致的不可控算成有趣的不确定性。若一个片段难以参与，先分辨输入和反馈是否有效，再判断该关系是否不成立。

## 7. 分支、验证与 main 选择

实验实施全部在分支进行。规划文档当前可留在 main 工作区；本轮没有创建上述分支，也不提交或推送。

- 独立实验从明确、稳定的共同基准开始，记录准确提交；新规划文档提交后的 main 可作起点，但不能把未验收实验悄悄作为公共依赖。
- 需要沿用一个发现时，从它建立明确变体并记录来源；跨方向比较要说明继承的改动。优先避免四个实验互相依赖后才可运行。
- 不为了切分支覆盖用户工作；保存实验的可返回版本和简短记录。无趣方向可以停止，不要求删除历史或整理成通用系统。
- 运行与改动相符的现有检查：确定性行为先有可复现检查；运行 `tests/test_runner.gd`，几何／接线／Wake 涉及 `tests/test_physics_scenarios.gd`，音频接线涉及 `tests/test_audio_scenarios.gd`，视觉涉及捕获与截图检查。阶段完成运行 headless import 和主场景 1200 帧，日志写入仓库 `.godot/`。
- 实验故意改变的旧规则应列为明确的对照差异，对应测试在分支调整并保留解释；不能为了全绿批量放宽未改变规则的断言，也不把旧规则失败一律认定为不许探索。机器验证服务于可靠试玩，不能判断关系是否成立。
- **保留仅代表候选**。用户实际体验后挑选符合核心关系的部分，再整理进入 main；完成度、投入成本和机制数量不构成选择理由。
- 合入前处理临时代码和交互冲突，同步 main 的设计契约、说明及相关测试，完成适用回归并再次试玩组合结果。此时才决定是否需要正式状态、共享机制或架构提取。远端写入仍按具体授权执行。

首批结束的交付是实验观察、三类结果及下一轮方向，不强制输出一个 V0.2.0 发布版本。组合可能只保留一个片段，也可能仍不足以进入 main。

## 8. 规划阶段完成与停点（历史；当前状态见顶部）

- 已确认：用户提出的设计原则、搜索方法与边界，见[原则文档](../design/v0.2-exploration-principles.md)。
- 已规划：四个首批体验假设、起始顺序、可选实现手段、对照、观察方法、变形方向及分支流程。
- 待体验：所有事件是否成立、是否值得保留、wake／rebounce 是否有感知区别、哪些机制值得正式化。
- 未开始：实验分支、运行时代码、临时素材／反馈、实验测试与人工试玩。
- 下一步：用户要求启动后，从 E01 的可玩片段开始；无需用户先补全行为或数值规格。本轮到此停在实施之前。
