# V0.1.5 — Paddle Support / Interaction Wake
2026-09-10：用户批准实现。本文件替代V0.1.3中Wake输入映射及Ground-only支撑契约，其他Physics/Vitality/视觉/音频基线保留。

## 契约
- Activity仍为ACTIVE/DECAYING/RESTING；Support独立为NONE/GROUND/PADDLE。Paddle低活力、低速下降顶面接触可以停稳；正常接球不变。
- 支撑静止不重复制造碰撞、Vitality损耗、Combo或声音。Paddle横移不承载球；失去顶面覆盖后保持Vitality并恢复重力，包括零速度RESTING。
- 输入使用受Paddle可达范围约束的新目标位移，非平滑后的Paddle velocity；50 ms内累计无符号输入距离。初始Strong阈值12.5 px，范围200 px、Rest延迟0.12 s保留。慢输入窗口过期后重新累计，停止输入不延迟提交。
- 连续弱交互立即按累计强度提供轻微Core几何压缩（最多6%），Paddle不因弱交互或Strong Wake闪动，仅真实碰撞触发Paddle反馈；不改变真实碰撞形状、Velocity、Vitality或RESTING，不播放专门Wake声，不消费强Wake资格。停止后恢复形状，Core颜色/Glow仍只表达Vitality、Trail只表达Velocity。
- Strong达标时一次恢复0.15最大Vitality并离开RESTING，必要时固定向上350 px/s；不注入水平速度，不随超阈值输入改变高度。无支撑的运动球仅恢复活力，不再加启动；同帧真实碰撞已启动运动时不叠加。
- Paddle始终真实碰撞，挡住起跳路径时正常下沿反弹。激活signal统一驱动Rules计时和既有Strong音效；Paddle闪动只由真实碰撞触发。
- 新输入在Ball物理步之后处理，使当步碰撞/支撑先完成；采样仅在新输入时提交，窗口过期/出范围/支撑丢失/复位清空，不存在到期自动补发。
- 不新增承载、摩擦、sweep、随机/动态音高、全局管理器或替代碰撞系统。

## 实施顺序
1. 新契约确定性回归先失败，再实现Activity/Support与输入/输出分离。
2. 替换已被新契约取代的旧Wake断言；保留普通Surface、边界、Vitality、音频密度回归。
3. 真实场景覆盖Ground/Paddle支撑、丢失支撑、弱强连续、左右/远离、阻挡、低速停稳、碰撞与Wake同帧。
4. 运行确定性、物理、音频场景、headless import、1200帧；捕获弱响应视觉，检查三通道未混用。
5. 同步受影响入口与状态，停在人工试玩；本轮不自动提交/推送。

## 人工门
连续弱反馈是否可感知又不似起跳；阈值与50 ms节奏；固定启动是否自然；Paddle不承载横移的手感；移开/阻挡/支撑重新唤醒。数值是实现初值，不宣称听感/手感已验收。

## 实际实现与验证（2026-09-10）

- BallController增加局部SupportKind与Paddle引用；低活力（<=0.08）且Ball速度<=45的下降顶面接触进入支撑，中心须在顶面有效覆盖内；支撑维持使用0.5 px容差，边缘1 px退让。它不实现平台摩擦或速度继承，也不声称完整相对接触动力学。
- Paddle输入取新clamped target变化量，默认场景Ball先完成碰撞/支撑，再接收Paddle当步输入；实际Paddle速度仍用于其运动记录，不再连接Wake。零输入样本只用于范围取消，平滑尾段不累计。
- BallController弱反馈signal与Strong wake_committed分开；Main仅在成功Strong时重启Rules计时与现有音效，音频资源/音量不变。F1替换旧水平/竖直冲量系数为Interaction distance与Launch speed。
- 新契约回归先失败（缺少独立互动入口），实现后通过；支撑丢失导致旧累计量误合并也先用回归复现，再调整处理顺序。
- 本轮确定性393、physics_scenarios847、audio_scenarios38 checks通过。旧速度映射断言由新契约替换，计数不可直接视为历史测试的简单累加；普通Gravity/SurfaceResponse/Vitality原回归仍保留。
- headless import、主场景1200帧均退出0；没有脚本错误。仍有既有Windows根证书读取和编辑器用户配置保存环境提示；本次主场景未报告退出资源占用。
- capture_visual_baseline生成六张960×720图片，检查Ground/Paddle弱形变：中心与支撑几何保持，Glow未随弱输入变化、静止无Trail；弱响应动态手感仍需人工判断。截图与日志均在忽略的.godot内。
- 文档链接/差异检查通过。未提交或推送本轮实现。

当前状态：用户已验收总体体验；随后按明确要求修复非碰撞Paddle闪动，完成关键回归并作为V0.1.5 Paddle interaction model收口。已知高速Paddle sweep及configure开局副作用仍未扩展；未建立承载摩擦、随机启动、动态音高或V0.2体系。
