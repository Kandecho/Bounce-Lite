# Bounce Lite：产品概览

本页维护当前产品定位与持续约束。当前发布事实见[0.2.1](releases/v0.2.1.md)，本阶段取舍及暂定实现见[当前计划](exploration/harvest-refinement-plan.md)，协作权限见[AGENTS](../AGENTS.md)。实现与验证入口通过[文档导航](README.md)查阅。

## 产品目的

一个可随时开始、随时结束的物理电子玩具。玩家用鼠标移动挡板，围绕一颗球产生自己的小目标；球和世界通过清楚、可理解的物理动作回应。

当前判断是“没有意义的好玩”：碰撞、弹出、拼合与摔碎本身值得发生，不依赖积分、资源、胜利、成长、任务或长期收益。筛选问题是：去掉外部奖励以后，玩家是否仍想让球再碰它一次？实际体验决定动作的取舍。

## 持续有效的产品约束

- 单球是主要注意中心，挡板是直接介入中介与真实物理表面；保留E01接触位置的有限偏转，球不成为完全可控工具。
- 表现行为，不解释内心；无输入只表示无输入，不推断玩家离开、观看或在场，也不据此触发存在性状态。基础机关不承担人格、持久记忆或奖励职责。
- 生命周期保持 ACTIVE → DECAYING → RESTING → Wake或Continue → ACTIVE。Wake由挡板动作直接触发、推力强；Continue由球停稳后发起、推力弱，玩家互动关系决定资格。围绕时间与空间打磨，不通过改起跳绕过挡板底面。
- 随机决定对象出现的时间、位置和停留；出现后的规则稳定可学习。允许自然共存和奇怪组合，不枚举组合的正确结果，不为排除偶发互动而隔离机制。
- 无分数、Combo、失败状态或完成清单；能量块不成为必须收集的资源，普通几何不额外补充Vitality。

## 实现职责与连续性

| 职责 | 契约 |
| --- | --- |
| Physics | 提交位置、速度、碰撞与支撑；真实运动先于状态／反馈通知 |
| Interaction | 整理挡板实际动作、介入意图和Wake请求；目标位置变化不等于实体有效移动 |
| Behavior | 判断倾向、生命周期与Continue资格；目前在球及其组件内，不因分类预建独立架构 |
| Feedback | 呈现结果，不暗中改变运动；跨层通过显式请求，Activity通知不改Physics |

- 保留可靠碰撞、有限资源、合法生成与可返回版本。种子和组合快照支持复现对象配置及随机进度，不冒充球轨迹或输入录像。
- 本体默认通过最小共享占用接口避让，未来有意重叠可显式退出；几何完整运动包络、门户双口、转子核心与能量块参与，外围场力和光效不占位，感应区实现不豁免本体避让。
- 生成、激活复查与组合恢复采用一致规则；有限重试无合法位置则延后。快照不兼容时明确拒绝，不静默重排世界。
- 第一批几何按完整包络避开底部回弹区和挡板完整横向路径；这是该族规则，不自动成为所有未来机制的永久禁区。平台实际支撑球或弹簧持球时保持关系连续，结束后再离场，不扩展为通用延寿系统。

## 技术与运行环境

当前采用Godot 4.7、GDScript、Compatibility，Windows为已验证平台；960×720逻辑视口、640×480默认窗口，缩放保持4:3，整个客户区是场地。启动与操作只在[根README](../README.md)维护，版本号以 `project.godot` 为源。重大底层技术路线变化按AGENTS处理。
