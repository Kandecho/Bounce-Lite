# V0.2 完整可玩片段：当前设计与实施口径

日期：2026-09-11。整理：Codex，依据用户最新明确指令。状态：原型已实现，机器与主代理技术／视觉检验通过，整体效果待用户体验。

## 本轮目标

创造一个充分展开的 0.2 形态原型，展示 Bounce Lite 核心概念的可能形态，再反向分析值得进入正式版本的元素。优先创造让玩家愿意停留几分钟的可玩瞬间，不追求设置界面、全量 UI 或产品形式上的完整度。机制数量和工程成本不先限制构想。

此前逐项小实验方法转为历史参照。本轮可以同时调整接触、环境、第三对象、恢复和视听，使它们组成完整过程；无需每项机制先独立通过用户验收。E01 的有限接触影响经用户实测可以保留，但其组合效果仍需检验。

## 用户确认的两项设计硬边界

1. Interaction / Physics 保持职责分离。交互及行为可以提出请求，实际运动、碰撞与支撑由物理入口提交；表现和状态通知不暗中接管运动。允许明确跨层交互，不要求沿用全部旧类名、参数或状态。
2. 球是提供想象空间的对象，不是桌面宠物，也不是单纯机械性物体。它可主动、可停顿、可回应，并给后续和解释留有余地。

旧的固定重力、恢复比例、Wake 公式、视听通道冻结和架构类型限制均为已有实现参照，不成为本次额外设计硬边界。无任务压力、共同关注和可读因果等历史方向仍有创作价值，不能被偷偷扩充为新的绝对禁令。

## 已授权的实施方式

- 音效、视觉、动画、光效、配色、参数和机制可以自主修改，不逐项要求用户选择候选。
- 高推理主代理负责目标、分派与接口约定、实际效果检验及重派修改；代码实现、测试和修复使用低推理子代理。
- 主代理维护文档和执行检验，不直接接手代码修复。子代理按文件所有权并行，共享接线统一负责。
- 原型在独立分支；main 不自动更新。保留简单对照及可返回版本，为后续拆解准备。
- 文件保护、素材来源与许可、Git 安全及机器／人工结论区分继续适用。

## 当前创作假设（不是新增用户硬约束）

一个可撞动的转子留下余转，余转影响可见气流；补能对象改变接下来的运动机会。玩家通过已认可的有限接触回应参与这个过程。球的短暂停顿与继续提供留白，世界余波和声音使刚才的共同作用能够延续。用户可以接、等、靠近某件东西或停手。

机制与数值在实现及主代理检验中可调整；若某个机制只是热闹而没有改善整体片段，可以移除。完整原型的判断不是功能数量，而是是否形成值得自由尝试与停留的过程。
