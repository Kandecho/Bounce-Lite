- 日期：`2026-09-08`
- 阶段：`V0.1 - Core Gameplay Design`
- 状态：技术方案已获用户确认；等待本书面规格复核后进入实施计划与代码实现
- Project Name：`Bounce Lite`
- UI Title：`Bouncing Ball`
- Engine：Godot `4.7.stable.official.5b4e0cb0f`
- Renderer：Compatibility
- Target：Windows
- Design Resolution：`960 × 720`

本规格只覆盖 Endless 核心原型。正式素材、正式音频、精修视觉、主题系统和后续玩法均不在范围内。

## 2. 原型问题与成功标准

V0.1 验证以下核心设计：

> Bounce Lite 是一个持续耗散的反弹系统。环境碰撞不会创造能量，并会造成不同程度的能量损耗；玩家通过挡板重新向球输入能量，使它保持活跃。

原型需要让玩家感知：

1. 接球会把球恢复到正常活跃状态；
2. 不参与时，球会经由环境碰撞逐步安静；
3. 休眠不是失败，移动挡板可以再次唤醒球；
4. 连续成功不会导致无限加速；
5. 即使没有 Game Over，接球和维持活跃仍有吸引力。

体验质量由人工试玩判断。机器验证只覆盖确定性规则、配置和基本集成。

## 3. 范围

### 3.1 本阶段实现

- 单一 Endless 模式；
- 无重力、封闭矩形空间、确定性反弹；
- CharacterBody2D Ball；
- 鼠标水平控制的 Paddle；
- Energy → Speed 映射；
- Wall、Top、Ground、Paddle 四类碰撞结果；
- Combo；
- ACTIVE、DECAYING、RESTING 状态；
- Paddle Wake 手势；
- 从最近一次 Active/Wake 开始到 Rest 的活跃时间；
- 程序化 Ball Core、Glow、Trail 和 Paddle；
- 极简文字 HUD；
- 无第三方测试框架的 Godot headless 自动化测试。

### 3.2 明确不实现

- Game Over；
- Classic、Recover 或模式选择；
- 排行榜、最高分、连续生存挑战或奖励系统；
- Paddle 分区、不同击球区或音色；
- 障碍物、特殊材质、空间变化或随机事件；
- Light/Dark、“荧光/暖阳”主题系统及主题切换；

- 正式配乐和正式音效；
- Energy 数值或 Energy Bar；
- 键盘作为 V0.1 必需输入。

## 4. 技术方案

采用 Godot CharacterBody2D 与内建碰撞查询。Ball 在 `_physics_process()` 中调用 `move_and_collide()`，使用 Godot 返回的 `KinematicCollision2D` 法线计算反射；不使用 RigidBody2D，也不自行实现几何相交或扫掠检测。

选择理由：

- CharacterBody2D 不会被引擎自动施加重力或力，速度和能量映射可以完全受项目规则控制；
- `move_and_collide()` 提供碰撞对象、法线和剩余运动信息，适合明确编写反弹响应；
- 能量计算保持为不依赖 SceneTree 的纯规则对象，可在 headless 测试中确定性验证；
- 规则、输入、视觉和 UI 通过信号与窄接口连接，不把全部职责写进 Ball。

## 6. 组件职责与接口

### 6.1 PrototypeTuning

`PrototypeTuning extends Resource` 是 V0.1 的集中调参入口。所有运动、能量、Wake 和基础视觉参数从此对象读取；控制器中不得复制对应裸数值。

初始参数：

| 参数 | 初始值 | 含义 |
| --- | ---: | --- |
| `max_energy` | `1.0` | 正常可维持能量上限 |
| `active_speed` | `360.0 px/s` | `current_energy == max_energy` 时的正常活跃速度 |
| `max_speed` | `520.0 px/s` | 运动层绝对安全上限；V0.1 正常能量映射不主动达到该值 |
| `active_threshold_speed` | `300.0 px/s` | ACTIVE 与 DECAYING 的初始分界 |
| `rest_threshold_speed` | `35.0 px/s` | 进入 RESTING 的速度等价值 |
| `wall_energy_retention` | `0.985` | 左右墙碰撞后的能量保留率 |
| `top_energy_retention` | `0.985` | 顶部碰撞后的能量保留率 |
| `ground_energy_retention` | `0.75` | 地面碰撞后的能量保留率 |
| `wake_speed` | `330.0 px/s` | Wake 后恢复的速度等价值 |
| `wake_paddle_velocity` | `450.0 px/s` | 有效 Wake 水平速度阈值 |
| `wake_hold_seconds` | `0.08 s` | 必须连续超过阈值的时间 |
| `paddle_smoothing` | `18.0` | 基于 delta 的指数平滑系数 |
| `ball_radius` | `16.0 px` | Ball Core 与 CircleShape2D 半径 |
| `paddle_size` | `Vector2(150, 18)` | Paddle 视觉与碰撞基线 |
| `trail_max_samples` | `16` | 满活跃度时 Trail 最大采样数 |

这些值是调试起点，不是最终产品常量；调整只修改集中配置和对应测试期望。

### 6.2 BallEnergyModel

`BallEnergyModel extends RefCounted`，不访问 Node、输入或渲染 API。

公开状态：

```gdscript
enum ActivityState { ACTIVE, DECAYING, RESTING }
enum SurfaceKind { WALL, TOP, GROUND, PADDLE }

var current_energy: float
var max_energy: float = 1.0
var state: ActivityState
```

约束：

```text
0 <= current_energy <= max_energy
```

速度映射：

```text
speed = active_speed * sqrt(current_energy / max_energy)
speed = min(speed, max_speed)
```

反向映射：

```text
energy_for_speed(v) = max_energy * (clamp(v, 0, active_speed) / active_speed)^2
```

这里将 `max_energy` 定义为“正常可维持能量上限”，对应约 `360 px/s`。`max_speed = 520 px/s` 是防止数值或未来附加运动造成失控的硬上限，不是 Paddle 每次接球的目标速度。该解释同时满足 `current_energy = max_energy` 与“正常活跃速度约 360、最大速度约 520”两项决策。

公开方法：

```gdscript
func reset_active() -> void
func speed_for_current_energy() -> float
func energy_for_speed(speed: float) -> float
func apply_environment_collision(kind: SurfaceKind) -> void
func restore_from_paddle() -> void
func enter_rest_if_needed() -> bool
func wake() -> bool
func activity_ratio() -> float
```

环境碰撞：

```text
Wall:   current_energy *= wall_energy_retention
Top:    current_energy *= top_energy_retention
Ground: current_energy *= ground_energy_retention
```

三个保留率都必须位于 `[0, 1]`。每次修改后统一 clamp，因此普通环境碰撞满足 `Energy_out <= Energy_in`。

V0.1 不增加按时间持续扣除的隐藏 Energy drain。Decay 只来自 Wall、Top 和 Ground 碰撞；若人工试玩认为进入 Rest 太慢或太快，优先调整集中登记的保留率。

Paddle 碰撞：

```text
current_energy = max_energy
```

Wake：

```text
wake_energy = energy_for_speed(wake_speed)
current_energy = wake_energy
```

状态完全从 Energy 导出：

```text
RESTING  current_energy <= energy_for_speed(rest_threshold_speed)
DECAYING rest_threshold < current_energy < energy_for_speed(active_threshold_speed)
ACTIVE   current_energy >= energy_for_speed(active_threshold_speed)
```

状态不直接指定任意速度；速度始终重新从 Energy 映射。进入 RESTING 时，运动层把速度向量设为零。

### 6.3 BallController

`BallController extends CharacterBody2D` 负责：

- 保存单位运动方向；
- 从 BallEnergyModel 取得标量速度；
- 在 `_physics_process(delta)` 使用 `move_and_collide(velocity * delta)`；
- 使用碰撞法线 `direction.bounce(normal).normalized()` 计算确定性反射；
- 根据 collider 的 `surface_kind` 调用能量模型；
- 将更新后的标量速度重新应用到方向；
- 以 `max_speed` 作为最终安全 clamp；
- 进入 RESTING 时停止运动；
- Wake 时按 Paddle 移动方向生成向上的确定性启动方向。

单帧最多处理 `4` 次碰撞和剩余运动，防止角落或较大 delta 下穿透，同时避免无限碰撞循环。碰撞检测与接触信息由 Godot 提供，这不属于完全手写碰撞求解。

信号：

```gdscript
signal surface_hit(kind: SurfaceKind, energy_before: float, energy_after: float)
signal paddle_hit(energy_before: float, energy_after: float)
signal activity_state_changed(previous: ActivityState, current: ActivityState)
```

规则协调器使用的公开方法：

```gdscript
func start_active(direction: Vector2) -> void
func wake_from_paddle(paddle_velocity_x: float) -> bool
func is_resting() -> bool
```

Paddle 只有在球从上方、向下运动并命中挡板顶面时才算成功接球。侧面或底面接触只进行反射并采用墙面轻损耗，不增加 Combo，也不恢复能量。

### 6.4 PaddleController

`PaddleController extends CharacterBody2D` 负责：

- 读取当前 viewport 中的鼠标 X；
- 把目标 X clamp 到 Game Area 左右边界，并计入挡板半宽；
- 使用 delta 驱动的指数平滑移动，避免帧率相关的固定 lerp；
- 根据实际位置差计算 Paddle 水平速度；
- 不允许垂直移动；
- 检测连续 Wake 手势。

Wake 手势：

```text
abs(paddle_velocity.x) >= 450 px/s
并连续保持 >= 0.08 s
```

低于阈值时累计时间清零。只有 Ball 为 RESTING 时 EndlessRules 才接受 Wake 信号，因此正常游戏中的快速移动不会重复触发 Wake。

信号：

```gdscript
signal wake_gesture(velocity_x: float)
```

为便于确定性测试，鼠标读取与位置更新分离：`set_target_x(value)` 可由测试调用，生产路径由 `_unhandled_input()` 或 viewport mouse position 更新目标。

公开方法：

```gdscript
func set_horizontal_bounds(left: float, right: float) -> void
func set_target_x(value: float) -> void
func advance_motion(delta: float) -> void
func advance_wake_detector(velocity_x: float, delta: float) -> bool
```

### 6.5 EndlessRules

`EndlessRules extends Node` 是规则协调器，不直接移动 Ball 或 Paddle。

状态：

```gdscript
var combo: int = 0
var active_time_seconds: float = 0.0
var timer_running: bool = true
```

规则：

- 成功 Paddle hit：`combo += 1`；BallEnergyModel 恢复到 max_energy；
- Ground hit：`combo = 0`；不结束、不重置 Ball；
- 进入 RESTING：停止活跃计时；
- Wake：活跃计时归零并重新开始；调用 BallController 唤醒；
- 初次启动视为一次 Active 周期，Timer 从 `0` 开始；
- Wall/Top 不改变 Combo；
- 不存在 Game Over 状态或信号。

信号：

```gdscript
signal combo_changed(value: int)
signal active_time_changed(seconds: float)
signal rest_started()
signal wake_started()
```

可测试规则入口：

```gdscript
func handle_paddle_hit() -> void
func handle_surface_hit(kind: BallEnergyModel.SurfaceKind) -> void
func handle_activity_state_changed(state: BallEnergyModel.ActivityState) -> void
func handle_wake_gesture(velocity_x: float) -> bool
func advance_active_time(delta: float) -> void
```

### 6.6 BallVisuals

`BallVisuals extends Node2D` 只消费 Energy、ActivityState 和 Ball 位置，不修改玩法状态。

- Core：程序化白色圆；
- Glow：2–3 层低透明圆，强度和半径按 `activity_ratio` 连续插值；
- Trail：按移动距离采样最近位置，以圆点或短线段绘制；
- ACTIVE：最多 `16` 个样本；
- DECAYING：样本上限和透明度随 activity ratio 连续减少；
- RESTING：清空 Trail，仅保留最低强度 Glow；
- 不使用复杂 Shader 或 Particles。

原型采用中性深色背景，以便观察 Glow/Trail；它不命名为“荧光”主题，也不建立主题切换系统。

公开更新入口：

```gdscript
func set_activity(energy_ratio: float, state: BallEnergyModel.ActivityState) -> void
func record_ball_position(global_ball_position: Vector2) -> void
```

### 6.7 PrototypeHUD

HUD 只显示：

```text
COMBO 0
TIME 00:00
```

- 无边框、无卡片、纯文字；
- 不显示 Energy 数值或进度条；
- Timer 表示从最近一次 Active/Wake 开始到进入 Rest 的当前活跃时间；
- Timer 不改变难度、不触发失败、不作为强制成绩目标；
- Timer 通过独立接口消费 EndlessRules 数据，未来可以移除而不影响 Ball 或规则。

当前使用 Godot 默认字体作为原型占位，不下载或打包正式字体。

HUD 通过以下方法接收规则数据，不读取 BallEnergyModel：

```gdscript
func set_combo(value: int) -> void
func set_active_time(seconds: float) -> void
```

## 7. 事件流

### 7.1 环境碰撞

```text
BallController detects collision
→ classify surface
→ BallEnergyModel applies retention
→ derive ActivityState and scalar speed
→ reflect direction using collision normal
→ BallVisuals receives new activity ratio
→ EndlessRules handles Ground combo reset when applicable
```

### 7.2 Paddle 接球

```text
valid top-face Paddle hit
→ BallEnergyModel.current_energy = max_energy
→ speed returns to active_speed, capped by max_speed
→ EndlessRules.combo += 1
→ BallVisuals restores full active Glow/Trail range
```

### 7.3 Rest 与 Wake

```text
Energy reaches rest threshold
→ derived state becomes RESTING
→ BallController velocity = Vector2.ZERO
→ Trail clears and Glow becomes minimal
→ EndlessRules pauses active timer

Paddle exceeds Wake threshold for 0.08 s
→ PaddleController emits wake_gesture
→ EndlessRules verifies Ball is RESTING
→ BallEnergyModel sets wake_energy
→ BallController launches upward, biased by Paddle movement direction
→ Combo remains unchanged at its current value, normally 0
→ active timer resets to 0 and resumes
→ derived state becomes ACTIVE
```

Wake 启动方向：

```text
Vector2(sign(paddle_velocity_x) * 0.35, -1.0).normalized()
```

## 12. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| `max_energy` 与 `max_speed` 被误解为同一上限 | 明确 max_energy 对应正常活跃速度 360，520 仅为运动安全上限 |
| Corner collision 单帧重复处理 | 限制每帧最多 4 次碰撞；剩余运动小于 epsilon 时停止 |
| Paddle 底面误算接球 | 只接受向下运动且法线主要朝上的接触 |
| Wake 被鼠标抖动触发 | 同时要求速度阈值与连续 0.08 s；低于阈值立即清零 |
| Decay 过慢或过快 | 所有保留率集中配置；人工试玩后只调参数，不改职责边界 |
| Glow/Trail 影响 Compatibility 性能 | 使用少量程序化 draw call，不使用复杂 Shader/Particles |
| Timer 形成成绩压力 | 仅显示当前活跃周期；与难度、失败和排行榜完全解耦 |
