## Changed

### C1：显式物理停稳，Activity 仅通知

[BallController](../../scripts/ball/ball_controller.gd) 的 `_on_vitality_state_changed()` 仅刷新表现，不写 Velocity、Position、Support 或休息／交互采样状态。状态的统一通知保留在 BallVitalityModel；移除了无运行时监听者的控制器重复转发。

Ground SurfaceResponse 的 settle 许可与低活力门、Paddle 的低速低活力顶面判定、异常地面恢复，在各自明确的物理入口调用 `_commit_resting_settle()`：先速度归零、应用支撑位置，再明确开启新的交互休息窗口，最后提交 RESTING。支撑丢失清空旧交互样本的既有规则保留；没有以“解耦”为理由取消必要的跨层事件。

新增 [test_design_boundaries.gd](../../tests/test_design_boundaries.gd)，修复前复现 11 个失败，覆盖 Activity 转换不改速度／位置／交互资格、configure 不开局、Ground/Paddle 的监听者看到已提交的物理结果。原有测试中用状态转换暗中构造静止球的夹具，改为明确设置静止位置之外的运动／交互初值；生产停稳行为仍由真实碰撞场景验证，未把物理断言改成单纯状态断言。

### Combo 与旧 Rules / HUD 移除

删除 `EndlessRules`、`PrototypeHUD`、对应场景节点和脚本 UID，以及旧 `test_endless_rules.gd`。移除 Combo 计数／清零、常驻 Combo Label、旧 Timer Label、Main 中命中到规则的接线、Wake 重置时间和 RESTING 暂停时间。音频对照测试去掉了已不存在的成绩快照，保留 Physics / Vitality / State 等价断言。

检查 `scripts/`、`scenes/`、`tests/`，无 Combo、旧 Rules、旧 HUD 或活跃时间规则残留。历史文档中的 Combo 仅作为历史记录保留，不是隐藏成绩实现。

### 开发计时器

[RuntimeTuningPanel](../../scripts/dev/runtime_tuning_panel.gd) 自行累计 `observation_seconds`，F1 面板内显示 `DEV ELAPSED … s`；默认隐藏，关闭面板期间继续累计。它无 Ball、Activity、Vitality 或 Interaction 依赖。Wake 不重置，RESTING 不暂停；重新配置或显示／隐藏面板也不归零。负 delta 不倒退。

这是本次运行的开发过程计数器，开发者可读两个时刻的差值观察区间，不是自动记录一次运动的时长，也不新增状态事件日志。未添加玩家操作、评分、计时挑战或计时器控制玩法的路径。

### 健康度清理

- `configure()` 配置并复用模型依赖，不再隐式 `start_active()`，已有 Velocity、Position、Activity 和交互生命周期保持；重新提供 max_vitality 时只维持活力数值边界。`start_active(direction)` 是唯一显式开局入口，首次未配置调用也尊重传入方向。Main 仅开局一次。
- 移除控制器无用的 `surface_hit`、`paddle_hit`、`vitality_changed`、`bounds_recovered`、`weak_interaction` 和重复 Activity 转发；移除模型无监听的 `vitality_changed`。保留实际使用的 Surface、Paddle contact、Wake 和模型 Activity 通知。
- `interaction_strength` 改为局部计算值；弱反馈测试检查真实视觉几何响应，不再为测试保留运行时死信号。Wake 消费标记改在成功转换后提交，现有成功路径行为不变。
- 场景显式设置 Ball `process_physics_priority=-10`，Paddle 保留默认 0，固定碰撞／支撑先于输入的顺序；场景测试锁定该关系，不再仅依赖兄弟节点书写顺序。
- `ball_radius` 从 Ball Visuals 分组移至 Shared Geometry，注释明确物理半径与未形变 Core 共用；`paddle_size` 同样注明物理／外观共享。增加场景碰撞形状与 tuning 一致断言。不拆分尺寸、不新增动态几何系统、不改半径或外观。
- `project.godot` 标记阶段为 `v0.1.6-design-boundary-consolidation`。

## Design Decisions

| 决定 | 本轮处置 |
| --- | --- |
| Activity 不直接控制 Physics | 模型转换与通知不执行速度、位置或支撑变更；明确物理入口先停稳再提交 RESTING。 |
| Physics 与 Interaction 允许相互作用 | 碰撞可改变活力及 Activity；Wake 可显式恢复活力并按需启动。不追求隔绝两层。 |
| Paddle = Surface + Interaction Medium | 保留真实碰撞、支撑和标量交互，不作为 Ball 的方向控制器。 |
| Vitality 影响运动维持能力 | 保持既有碰撞恢复系数及活力恢复；不指定方向、不新增时间衰减。 |
| Combo 删除 | 不保留隐藏成绩。旧审查与旧计划提及 Combo 的文字属于历史，不再具有执行效力。 |
| Timer 为开发工具 | 用户本轮指令取代 Cross Review 的“可留活跃时长 Timer”建议；计数器只累计过程时间，不绑定球状态。 |
| 视觉保持 | RESTING 固定底光／状态色继续作为已验收特例，未按审计差异重设计；无效 Paddle 的既有形变分类也不改。 |
| Paddle 支撑与异常恢复 | 明确为 BallController 的物理入口，普通 SurfaceResponse 保留原模型；未迁移为新架构层。 |

审计处置对应：Codex C1、D1、R2、R5 已由本轮实现解决；R1 用显式物理优先级与场景断言收紧；C2 的“支撑丢失取消交互样本”是保留的显式规则。D2 视觉例外、M1 时间衰减、R3 音频密度和 R4 sweep 在下方列为保留限制。Claude 关于参数恢复、方向、无效 Paddle 外观的建议不构成授权，本轮未实施。

## Known Limitations

- **P2 — 体验仍需人工复核**：V0.1.5 历史验收保留；本轮不替代用户试玩。建议观察无成绩 HUD 的注意力体验、F1 计时用途，以及 Ground/Paddle 停稳和 Wake 的连续手感。机器通过不等于人工已验收。
- **P2 — Vitality 与视觉例外**：保留有效 Paddle 的既有恢复比例、Ground 衰减与 RESTING 固定底光。没有独立时间衰减；不存在按本轮新设定的活力恢复模型。
- **P2 — 几何仍有两处声明**：tuning 与场景形状通过注释和测试保持一致；不是运行时单一数据源。当前不开放动态尺寸编辑，改几何必须同步两处并跑几何场景。
- **P2 — 同帧验证边界**：显式物理优先级与顺序断言已加入；原场景测试大量手动驱动物理步骤。1200 帧是实际主循环冒烟检查，不是所有输入相位的自动化穷举。
- **P2 — 音频与接触表现**：保留密度抑制，成功 Wake 不保证每次都能越过最近碰撞音的抑制窗口；无效 Paddle 声音与几何形变沿用各自既有分类。没有扩展音效或调参。
- **P3 — Paddle sweep / 方向影响**：无高速横扫接触补偿、平台承载、摩擦或方向传递；未来讨论需独立授权，未纳入 V0.2.0 承诺。
- **历史清理范围**：可达分支／标签历史移除临时 Session trailer，保留作者与 AI 署名。旧克隆、回滚文件或托管方不可达对象可能仍留存旧哈希内容，不属于本次 refs 更新的删除保证。

以上保留项不扩大本轮版本范围。本报告随 V0.1.6 实现提交与版本标签发布；V0.2.0 仍未授权、未启动。
