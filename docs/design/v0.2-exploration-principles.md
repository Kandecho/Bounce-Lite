# V0.2 体验空间搜索：设计原则

日期：2026-09-10。整理：Codex。来源：用户在本轮对话中明确确认的设计原则及探索边界；本文为整理稿，不是附件原文的归档副本。

**状态：设计原则已确认；探索计划已建立；实验实施尚未启动。用户要求本轮停在具体实施之前。** 实验假设与建议顺序见[第一阶段探索计划](../exploration/v0.2-exploration-plan.md)，其中的具体事件尚无试玩结论。

## 1. 探索问题与文档效力

> 什么样的事件，会让玩家产生“我和它在玩”的感觉？

V0.2 采用体验空间搜索。已有文档和实现用于提供参照、比较差异，不要求所有实验围绕现有机制演进。先寻找值得再次经历的事件，再决定哪些机制值得正式化；不预先承诺正式版本的功能清单或架构。

本文是后续探索的设计判断依据。[V0.1.6 基线](design-baseline-v0.1.6.md)仍说明当前 main 的可玩实现；历史设计、审查和此前对话中的候选路线不覆盖本文。此前建议的“先做方向 Wake、再细分休息、最后加风场”不再作为固定开发顺序；独立 Behavior 层、wake／rebounce 分类和新增状态均未成为要求。

规划整理可更新 main 工作区中的文档；实验运行时代码全部在分支进行。本轮不创建实验分支、不修改游戏代码，不把计划建立视作实验已经获准开工。

## 2. 共同互动与自主性

Bounce Lite 的核心不是控制球，而是与一个具有自主性的对象共同互动。玩家能够表达意图、产生影响，结果不能完全由玩家决定。

- 可学习规律是必要的；玩家应有机会理解动作和结果之间的关系。
- 可感知影响是必要的；球的后续不能与玩家的介入毫无关系。
- 可以调整球的运动倾向；不以玩家操控球精确完成目标为方向。
- 球不是玩家控制器，挡板不是遥控器。球的当前运动、状态、接触与世界因素共同参与结果。
- “结果不完全由玩家决定”不要求每次相同条件都掷随机数。先建立规律，再判断是否需要在规律上增加变化；不靠随机拒绝、任意改向或故意失灵制造自主感。

自主性可以通过运动延续、时机和环境关系体现，不要求球具备更多主动动作或一套角色 AI。

## 3. 目标、奖励与对象

不反对目标、奖励或具体对象，反对系统强制目标化。

能量块可以存在，接触可以产生明确效果，玩家可以主动希望球碰到它。判断标准是“谁在推动目标结构”：玩家自发产生并可随时改变的目标属于互动；系统要求完成的目标属于任务。

实验不设置必须收集、玩家表现数值评价、完成清单或完成压力。没有碰到对象、没有延续某种状态、停下操作，都不自动构成失败。奖励可以改变之后发生的事，无须成为玩家成绩。

开发参数、调试数据和实验编号仅供开发者观察，不呈现为玩家评分。不能因为一个事件存在奖励就排除它，也不能因为删掉分数 UI 就认定它没有任务压力。

## 4. 事件优先于机制

每个实验先写清希望玩家经历的瞬间和一个主要体验假设，再选择足以呈现它的机制。

- 验证“世界改变轨迹后是否出现新的互动可能”，再选择风、引力、弹性结构或其他手段。
- 验证“停下来后是否仍像正在互动”，再选择停顿、恢复、反馈或再次启动的做法。
- 一个实验可以包含多个临时机制，但主要回答一个体验问题。
- 第一阶段优先区分不同设计方向，不以工程成本最低作为排序依据。

## 5. 保持模糊性

行为提供投射空间，结果留下解释余地。产品不通过人格设定、解释性文字或明确情绪标签告诉玩家球在想什么。

设计目标是让玩家愿意将球理解成某种伙伴，不要求玩家知道“球是什么”。实验名和开发记录可描述假设，但不把这种解释写进球的台词、状态标签或试玩提示。用户自发的解释可以作为观察记录，不能据此擅自固化为球的人格。

## 6. 当前重点探索范围

### 接触与意图表达

优先验证玩家动作与球是否形成一种可理解的语言。可以探索接触位置、接触时机、挡板运动及反馈差异；目标是感知影响与理解规律，不是提高操作精度。不将方向回应限定在休息后 Wake，也不预先选定接触分区、速度映射或启动公式。

### 停顿、恢复与再次介入

先观察“一次互动内部的停顿、继续、节奏变化”与“重新介入带来的新开始感”是否被玩家感知为不同经历。wake／rebounce 的机制边界暂不固化；两者可以共享机制，也可以在实验后分化。

不为了语义差异提前建立新状态层。输入沉默只是观察到的输入事实，不能直接认定玩家已经离开；静静观看也可以是参与。

### 第三对象与环境

重点探索球和玩家共同影响第三对象、世界因素改变互动、双方共同关注某个目标。伙伴感可能来自“一起改变了某件事情”，无需只围绕让球更像角色展开。

## 7. 实验自由度与边界

实验阶段允许临时事件、参数、行为、视觉反馈及暂时不优雅的代码。后续实验获准启动后，在其体验假设范围内自主选择常规实现细节，不逐项要求用户决定数值或触发条件。

当前 main 的固定 Wake 参数、恢复方式、反馈曲线和无新对象限制是基线参照，不自动成为探索分支的禁区。实验记录应注明实际偏离，便于试玩比较和后续选择；这些偏离不自动修改 main 契约。

不预建通用事件系统、行为树或复杂调度，不为未来扩展提前抽象。机制可以共享已有代码，也可以局部临时实现；不以形式上的层数作为实验完成条件。临时实现仍须足够可靠，使玩家可以评价事件，而非碰撞错误、漏输入或错误反馈。

本计划不改变 Windows、Godot、GDScript、Compatibility、窗口基准或项目名称，不要求更换物理技术路线、安装依赖或建立正式素材流程。相关工程与文件安全要求继续适用。

## 8. 体验判断与选择

主要观察三个问题：

1. 哪些瞬间让玩家自然想再试一次？
2. 哪些瞬间产生“我和它一起做了某件事”的感觉？
3. 哪些瞬间只是“系统很酷”，没有形成关系？

| 结果 | 含义 |
| --- | --- |
| 保留 | 形成值得再次体验、符合核心关系的瞬间；保留候选，不等于立即合入 main。 |
| 变形 | 原假设不成立，但发现新的关系；下一轮改写假设，不必继续完善原机制。 |
| 搁置 | 只有机制新鲜感，或没有形成符合核心关系的体验；允许完全放弃实现方向。 |

未试玩或因故障无法判断时，状态仍是待试玩／待修复，不伪造上述结果。机器验证不能证明伙伴感，开发者推断不能冒充用户体验。

最终进入 main 的是最符合 Bounce Lite 核心关系的实验部分，不是完成度最高或代码最多的实验。组合后需要再次试玩；不保证多个单独有趣的事件叠加后仍然成立。
