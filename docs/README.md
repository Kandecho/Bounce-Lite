## 生成、保存、活跃与公开

这四个判断独立进行。对象曾经有用、已经存在或能够补充说明，不自动取得长期维护或公开的位置。比较其缺席或现实替代方案造成的损失、维护成本及承担者，保留完整承担当前职责的最小结构。

| 判断 | 标准 |
| --- | --- |
| 生成 | 当前决策、实现或交付存在具体缺失；优先更新已有权威内容，短任务不例行建立独立计划和报告 |
| 保存 | 仍承担复现、追溯、维护、来源或许可职责；保存必要结论或原件，不要求保留全部中间产物 |
| 活跃 | 当前工作实际依赖，效力和维护责任可辨；被替代或只剩追溯用途时退出当前入口及默认执行 |
| 公开 | 帮助他人运行、理解、验证或维护项目，且可按现有来源与许可分发；内部过程有保存价值也可只留私有档案 |

公开保留源码、必要媒体及来源、有效测试、权威说明和支撑当前选择的必要证据。完整分派、授权往返、本机诊断日志、原始反馈、备份和旧概念材料不默认分发。公开说明不依赖本机档案才能理解，原稿与审查署名在归档中保留。

临时保留应有现实理由和退出条件。已批准的长期方向可赋予过渡产物具体职责，一般的未来可能性不足以支持新框架或兼容层。规则和审查动作本身也需衡量成本，不把治理变成固定套数的产物。

## 测试的长期维护资格

- 长期回归保护当前契约、现实回归风险、支持中的兼容路径或开放缺陷；断言应识别实际错误，代价与风险相称。名称、年龄、调用频率和实现时有用都不能单独决定保留。
- 复用诊断／捕获工具应能回答仍会遇到的问题，并有可理解的输入、模式和输出；按问题运行，不全部纳入默认回归。截图输出本身不是自动视觉回归。
- 一次性探针不自动成为测试资产；任务结束保存必要结论，脚本无独立职责时退出工作树。保留历史通过证据不要求永久维护原捕获脚本。
- 合并或移除前核对真实调用、独立断言、模式／初态和替代覆盖；不能用“新版检查更多”推断全部职责已接替，也不能只因初态不同就继续保留。
- 新增或实质修改测试时说明长期职责，收尾复核保留价值；无需再为每个测试建永久台账。退出行为的断言应一并重审，不让过时测试反向限定产品。

## 决定与事实

已明确选择、授权内暂定实现、未决候选和后置是决定性质；已实现、机器验证、代理观察和用户反馈是实际状态。两维不能相互晋升：已经实现不等于永久规格，功能通过不等于美术定稿，受控可达不等于自然频率合适。

当前计划维护决定，问题登记维护反馈，版本说明保存发布事实，源码维护精确参数。更换权威来源时更新索引与依赖，不保留两套同时要求同步的规格。
